## 2. Availability and status

- **Code**: provided in full for the Zeek/UWF pipeline — RealMLP
  (`scripts/01`–`05`) and CatBoost (`scripts/06`), both SHAP + LLM
  agents — for the CasinoLimit SHAP+Agents pipeline (RealMLP and
  CatBoost, `scripts/casinolimit/`), and for the LSTM+xNIDS+Agents
  pipeline for both datasets (`scripts/lstm/`, see
  `scripts/lstm/README.md`).
- **Data**: the two ATT&CK-labeled datasets used in the paper are
  included directly (`data/processed/`, `data/casinolimit/`), so that
  the archive is self-sufficient — unlike the development repository
  where these files are regenerated locally and excluded from git.
- **Models**: all models are now included and directly reloadable —
  Zeek (RealMLP ×3, CatBoost ×2, LSTM) and CasinoLimit (RealMLP ×2,
  CatBoost ×2, LSTM) — with the retraining command documented in
  `models/README.md` and `scripts/lstm/README.md`.

### Alignment with Tables I/II/III of the paper

A systematic review of the paper against the code revealed several
discrepancies between the features/hyperparameters actually used by
the provided models and those declared in the paper. All discrepancies
affecting **CasinoLimit** (RealMLP, CatBoost, LSTM) and the **Zeek
LSTM** have been corrected by retraining the affected models with
exactly the declared features and hyperparameters:

- **CasinoLimit RealMLP/CatBoost** (`models/casinolimit/*.joblib`):
  retrained with exactly 7 Baseline features (Table I) and 17
  Behavioral features (Table II), and the Table III hyperparameters
  (RealMLP: "TD" tuned-default with no override; CatBoost:
  iterations=500, learning_rate=0.05, depth=8, Logloss). See
  `models/casinolimit/README.md` for the measured performance and for
  the Precision discrepancy observed on the Baseline representation
  (related to the TEST split imbalance, not a model issue).
- **CasinoLimit and Zeek LSTM**: both now consume exactly the Baseline
  representation (Table I — 7 features for CasinoLimit, 48 for Zeek)
  with the Table III hyperparameters (3 epochs, batch 256, no early
  stopping or epoch selection — an earlier version of the Zeek
  training used 30 epochs with best-F1 selection on VAL, now
  corrected). The Zeek feature set was entirely rebuilt
  (`scripts/lstm/zeek_data.py`) to use the same logic as
  RealMLP/CatBoost instead of the ad hoc features (raw ports, no TCP
  history indicators) inherited from the source notebook — which
  resolved a significant Recall gap (0.78 → 1.00 on TEST). See
  `scripts/lstm/README.md` for the full details of this investigation
  (two incompatible third-party checkpoints identified and discarded
  along the way).
- **Zeek RealMLP/CatBoost Behavioral**
  (`models/realmlp_zeek_binaire_behavioral.joblib`,
  `models/catboost_zeek_behavioral.joblib`): now also corrected. These
  models used an `EXPECTED_FEATURES` list of 63 features, including 4
  features not declared in the paper's Tables I/II
  (`avg_bytes_per_packet`, `bytes_per_second`, `pkts_per_second`,
  `src_unique_port_last_10` — theoretical total 48+11=59, not 63).
  `src/ids_pipeline/config.py::EXPECTED_FEATURES` was corrected to 59
  features (the 4 features removed, along with their occurrences in
  `FEATURE_DESCRIPTIONS`, `SEMANTIC_BUCKETS` and `DIRECT_FEATURES`),
  and both models were retrained with this exact list — verified
  directly against the columns learned by each model (`feature_names_`
  for CatBoost, `x_converter_.fitted_columns` for RealMLP): 59/59,
  identical to `EXPECTED_FEATURES`.

### Other known limitations of this artifact (explicitly stated)

 The raw Zeek exports (`data/raw/`) are not included (too large); the
   already-processed dataset (`data/processed/`) allows the training
   and the XAI/agents pipeline to be reproduced directly without going
   through this step again.


## 3. Reproducibility

With `data/processed/` and `models/` already provided, the following
steps can be reproduced immediately on the Zeek/UWF dataset (once
`mitre/mitre_techniques_behavioral.json` is rebuilt, cf. point 1
above):

```bash
pip install -e .
python scripts/05_run_shap_llm_pipeline.py --n-per-technique 5 --seed 42
```

To reproduce model training from scratch, see `models/README.md`. To
rebuild the dataset from the raw Zeek exports (not included), see
`data/README.md`.

## 4. License and anonymization

All identifying information (author name, personal local paths) has
been removed from this code for double-blind review (`README.md`,
`pyproject.toml`, `notebooks/exploration_pretraitement.ipynb`). The
model binaries (`models/**/*.joblib`, `models/**/*.pt`), including the
5 most recently added ones (`catboost_zeek_behavioral.joblib`,
`realmlp_binary_baseline.joblib`, `realmlp_binary_behavioral.joblib`,
`catboost_binary_baseline.joblib`, `catboost_binary_behavioral.joblib`),
have been verified (search for identifying strings) to contain no
identifying information.


****Original raw data not included (Zeek and CasinoLimit)** : due to
their size (several gigabytes before sorting/enrichment)**



**Expected variability in Agent 2 scores (Top-1/Top-5)**: the exact
values obtained when re-running a script may differ slightly from
those reported in the paper. Two normal causes for this: (1) the LLM
agents do not behave in a perfectly deterministic way across runs
(same prompt, same model), and (2) the test events sampled by default
(5 per technique) are not necessarily exactly the same ones used to
produce the figures in the paper. These variations remain minor and do
not affect the paper's qualitative conclusions (degradation under
permuted/constant fake SHAP, gaps between Baseline and Behavioral,
etc.), consistently reproduced regardless of the sample or the run.
